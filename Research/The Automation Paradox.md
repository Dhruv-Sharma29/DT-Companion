# ⚠️ The Automation Paradox

The trap sitting directly in front of this project. **8 Sep 2026**

> [!important] You cannot fix an AI-induced judgement deficit with more automated judgement.
> If the tool tells the team which insight matters, it has removed exactly the rep whose
> absence is the problem. You would ship a faster version of the disease. #key

## Why this is easy to walk into
The obvious build is: *feed in the messy evidence, AI returns the key insights and the
real problem.* It demos beautifully. It is also the thing that caused the problem —
[[AI Shifted the Bottleneck]] — applied one stage later.

## The design rule that follows
The product's job is to make reasoning **visible and accountable**, not to produce
conclusions. Legitimate moves:

| Do                                                        | Don't                       |
| --------------------------------------------------------- | --------------------------- |
| Show which claims rest on observed evidence vs. inference | Rank the insights for them  |
| Surface the weakest link in an argument                   | Pick the strongest argument |
| Make two team members' differing interpretations collide  | Merge them into a consensus |
| Ask the question they skipped                             | Answer it                   |
| Demand the evidence behind a claim                        | Supply the evidence         |

AI is allowed to do the **noticing**. The human must do the **committing**. #key

## The segment split this creates #insight
The paradox does not apply equally, and this splits the market cleanly:

- **Students** are here to *build* judgement → the tool must add productive **friction**.
- **Professionals** already have judgement and want **speed** → friction is a tax.

These want opposite products. Serving both with one interface is the most likely way this
project fails. Pick one — see [[Open Questions]].
